🗄️ Base de Datos — Objetos SQL

Vista: v_balance_contratos

-- Consultar balance de todos los contratos
SELECT * FROM v_balance_contratos;

-- Solo contratos vigentes
SELECT * FROM v_balance_contratos
WHERE estatus_contrato = 'Vigente';

Que hace: Une 3 tablas (contrato + patrocinadores + pagos) y calcula: monto pagado, saldo pendiente, % pagado, cantidad de pagos.

Triggers: Auditoria en pagos

-- Cuando INSERTAS un pago nuevo...
-- el trigger automaticamente registra en bitacora

INSERT INTO pagos (monto, ...) VALUES (21250, ...);
-- → trg_pagos_after_insert escribe en actividad_usuario

-- Cuando MODIFICAS un pago...
-- el trigger guarda antes/despues en JSON

UPDATE pagos SET monto = 25000 WHERE id_pago = 1;
-- → trg_pagos_after_update guarda diff en bitacora

Por que: Los pagos son datos sensibles (dinero). Aunque alguien ejecute SQL directo, queda la trazabilidad automatica.

Procedimiento: sp_resumen_financiero

-- Un solo llamado genera 4 reportes:
CALL sp_resumen_financiero('2026-01-01', '2026-12-31');

-- Result 1: Resumen de contratos
-- Result 2: Pagos recibidos
-- Result 3: Top-10 patrocinadores
-- Result 4: Contratos por vencer

Por que: Evita 4 round-trips a la BD. Un solo comando genera todo el dashboard financiero.

⚠️ Preguntas Trampa y Respuestas

PreguntaRespuesta Correcta
"Por que no MD5?""Esta obsoleto. Use pbkdf2:sha256, estandar actual de OWASP."
"Por que no Apache?""Stack Python/Flask, no PHP. Gunicorn para produccion."
"Que pasa si falla la BD?""Error handler + rollback automatico en transacciones."
"Como escalas?""Mover SocketIO a Redis + multiples workers."
"Que es un trigger?""Es codigo SQL que se ejecuta automaticamente al INSERT/UPDATE/DELETE. En mi caso, audita pagos."
"Que es una vista?""Es una consulta guardada que se usa como tabla. Simplifica JOINs frecuentes."
"Que es un procedimiento?""Es un bloque de SQL reutilizable. Mi sp resumen genera 4 reportes en 1 llamada."
